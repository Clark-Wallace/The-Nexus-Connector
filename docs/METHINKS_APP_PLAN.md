# MeThinks Application Development Plan

> A CLI/TUI application that generates project ideas AND produces AI-ready specification documents for downstream tools like Claude Code.

## The Problem

There's a "context cliff" between ideation and execution:

1. User talks to MeThinks → gets a project idea
2. User goes to Claude Code → has to re-explain everything
3. Downstream AI doesn't know:
   - User's actual skill level
   - Technology preferences/constraints
   - What "simple" means to this user
   - The reasoning behind the idea
   - Priority of features
   - Success criteria

**Result:** Wasted time, misaligned expectations, frustration.

## The Solution

MeThinks Application generates TWO outputs:

1. **The Idea** - Human-readable project concept
2. **The Spec** - AI-consumable project specification (`.methinks` or `PROJECT_SPEC.md`)

The spec file travels with the project and gives downstream AIs full context.

## Core Concepts

### Project Specification Document

A structured document containing everything an AI needs to execute:

```markdown
# Project: [Name]

## Context
- **Generated by:** MeThinks v1.0
- **User Skill Level:** beginner | intermediate | advanced
- **Session Date:** 2024-01-15

## Vision
[What this project is and why it matters to the user]

## User Profile
- **Experience:** [Languages/frameworks they know]
- **Learning Goals:** [What they want to learn]
- **Time Commitment:** [Hours per week, deadline if any]
- **Preference:** Guided explanations | Just code | Balanced

## Technical Requirements
- **Language:** Python 3.11+
- **Framework:** FastAPI
- **Dependencies:** [List with versions]
- **Environment:** Local development | Docker | Cloud

## Features (Prioritized)
### Must Have (MVP)
1. [Feature] - [Why it's essential]
2. [Feature] - [Why it's essential]

### Should Have (v1.0)
1. [Feature] - [Value it adds]

### Nice to Have (Future)
1. [Feature] - [Why it's deferred]

## Architecture Decisions
- [Decision]: [Rationale]
- [Decision]: [Rationale]

## Constraints
- [Constraint]: [Reason]

## Success Criteria
- [ ] [Measurable outcome]
- [ ] [Measurable outcome]

## Anti-Goals (What this is NOT)
- Not trying to [X]
- Explicitly avoiding [Y]

## Conversation Summary
[Key points from the MeThinks session that informed these decisions]
```

## Phase 1: CLI Foundation

**Goal:** Working CLI that captures context and generates specs

### 1.1 Core Data Models

```python
# methinks/models.py

@dataclass
class UserProfile:
    skill_level: Literal["beginner", "intermediate", "advanced"]
    known_languages: List[str]
    known_frameworks: List[str]
    learning_goals: List[str]
    time_commitment: Optional[str]  # "5 hours/week"
    explanation_preference: Literal["guided", "balanced", "minimal"]

@dataclass
class Feature:
    name: str
    description: str
    priority: Literal["must", "should", "nice"]
    rationale: str

@dataclass
class ProjectSpec:
    name: str
    tagline: str
    vision: str
    user_profile: UserProfile
    language: str
    frameworks: List[str]
    features: List[Feature]
    architecture_decisions: Dict[str, str]
    constraints: List[str]
    success_criteria: List[str]
    anti_goals: List[str]
    conversation_summary: str
    created_at: datetime
    methinks_version: str
```

### 1.2 CLI Commands

```bash
# Start a new MeThinks session
methinks new

# Resume an in-progress session
methinks resume [session_id]

# List saved sessions/specs
methinks list

# Export a spec to different formats
methinks export <session_id> --format md|json|claude

# Quick mode - skip guided flow, just capture idea
methinks quick "I want to build a CLI todo app"

# View a saved spec
methinks show <session_id>
```

### 1.3 Session Persistence

```
~/.methinks/

```

## Phase 3: AI Integration

**Goal:** Smart conversation that extracts structured data

### 3.1 Conversation Engine

```python
class ConversationEngine:
    """Manages the guided conversation flow."""

    phases = [
        DiscoverPhase(),    # What interests you?
        ExplorePhase(),     # Tell me more...
        CrystallizePhase(), # So you want to build X?
        ScopePhase(),       # What's essential?
        ProfilePhase(),     # What's your experience?
        RefinePhase(),      # Anything to adjust?
    ]

    async def advance(self, user_input: str) -> ConversationResult:
        """Process input and potentially advance to next phase."""

    def get_extracted_data(self) -> Dict[str, Any]:
        """Return structured data extracted so far."""
```

### 3.2 Extraction Strategy

Each phase has:
- **Goal:** What information to capture
- **Prompts:** How to ask for it naturally
- **Extractors:** How to parse responses into structured data
- **Validators:** When is this phase complete?

```python
class ExplorePhase(ConversationPhase):
    goal = "Understand the user's motivation and constraints"

    async def process(self, input: str, context: Dict) -> PhaseResult:
        # Use AI to have natural conversation
        # Extract structured data from the exchange
        # Determine if ready to move to next phase
```

### 3.3 Spec Generation

```python
class SpecGenerator:
    """Generates specification documents from session data."""

    def generate(self, session: Session, format: str = "markdown") -> str:
        """Generate spec in requested format."""

    def generate_claude_format(self, session: Session) -> str:
        """Generate Claude Code optimized format (CLAUDE.md style)."""

    def generate_json(self, session: Session) -> Dict:
        """Generate machine-readable JSON spec."""
```

## Phase 4: Export & Integration

**Goal:** Seamless handoff to downstream tools

### 4.1 Export Formats

**Markdown (default):**
```bash
methinks export session_123 --format md -o PROJECT_SPEC.md
```

**Claude Code optimized:**
```bash
methinks export session_123 --format claude -o CLAUDE.md
# Generates file structured for Claude Code's context system
```

**JSON (for programmatic use):**
```bash
methinks export session_123 --format json -o spec.json
```

### 4.2 Project Scaffolding (Future)

```bash
# Generate spec AND create project structure
methinks create "todo-app" --scaffold
```

## Technical Decisions

### Why CLI First?
1. Forces clean separation of concerns
2. All features discoverable through help/usage
3. Scriptable and composable
4. TUI is just a wrapper over CLI functionality
5. Easier to test

### Why Textual for TUI?
1. Already a dependency for Vibe Code
2. Pure Python, no external processes
3. Modern async support
4. Rich widget ecosystem
5. CSS-like styling

### Session Storage
- JSON for session state (resumable)
- Markdown for human-readable specs
- SQLite if we need querying (future)

### AI Provider
- Use Nexus Connector (dog-fooding our own tool)
- Default to cheapest provider for conversations
- User can override in config

---

## Success Criteria

1. **Complete Flow:** User can go from "I have no idea" to "here's a spec" in one session
2. **Useful Output:** Generated spec actually helps Claude Code understand the project
3. **Resumable:** Can pause and continue sessions
4. **Fast:** Conversation feels natural, not interrogation
5. **Flexible:** Quick mode for users who know what they want

## Example Session

```
$ methinks new

🤔 MeThinks: Hey! What's on your mind today?

> I want to build something with Python but I don't know what

🤔 MeThinks: No worries! Let's explore. What do you find yourself doing
   repeatedly that could be automated? Or is there something you wish
   existed?

> I spend a lot of time organizing my downloads folder

🤔 MeThinks: Ah, digital clutter! Classic problem. Tell me more:
   - What kind of files pile up? (images, documents, installers?)
   - Do you have a system you wish you followed?
   - How tech-savvy would you say you are with Python?

> Mostly screenshots and PDFs. I'm intermediate with Python.

🤔 MeThinks: Got it! So we're thinking about a **file organizer** that:
   - Watches your Downloads folder
   - Sorts screenshots and PDFs automatically
   - Maybe by date? Or content type?

   Does that capture it?

> Yeah, and it would be cool if it could read the PDF names and sort by topic

🤔 MeThinks: Smart! So some basic content analysis. Let me ask:
   - Should this run continuously in the background, or on-demand?
   - Local only, or would cloud backup be nice?
   - Is this for learning, or do you want something production-ready?

> On-demand is fine. Local only. Mostly learning but I want it to actually work.

🤔 MeThinks: Perfect. I've got enough to generate a spec. Here's what I captured:

   📋 Project: Downloads Organizer
   🎯 Goal: Auto-sort Downloads folder by file type and content
   👤 Skill: Intermediate Python
   ⏱️ Scope: Learning project that works

   Ready to generate the full spec? [Y/n]

> y

✅ Spec saved to: ~/.methinks/sessions/2024-01-15_downloads-organizer.md

🚀 To use with Claude Code:
   methinks export downloads-organizer --format claude -o ~/projects/downloads-organizer/CLAUDE.md
```
